# Course audit and compatibility changelog

The repository contains **24 original notebooks**. Each numbered entry below has a lecture copy at the root and a same-named, stripped-down copy under `clean/`. The other two are slide notebooks. The existing dev container uses a Python 3.10 base image and an unpinned package list.

The project pins the interpreter and uses the official CPU wheel pair for Windows. The lock also pins the search client, numerical stack and Jupyter components. DDGS 9.9.3 failed its live test with the resolved primp client. DDGS 9.16.1 and primp 2.0.1 passed the same query. See [validation](VALIDATION.md) for the scope of runtime coverage. [PyTorch installation matrix](https://pytorch.org/get-started/previous-versions/)

Runtime validation identified three fastai issues in the data-loader cell. With 2.8.7, `TfmdLists` reapplied the label transform to an encoded `TensorCategory`. Version 2.8.8 fixed that indexing error, then hit recursion formatting a transform. Version 2.8.11 fixed the recursion, but its published wheel omitted the `tvpad` import used by the lesson's squish resize. The 2.8.12 wheel supplies that import and incorporates both earlier fixes. The only package changes from the initial lock were fastai 2.8.12 and its required fastdownload 0.0.8. Comparing the 2.8.7 and 2.8.12 wheels confirmed identical Python syntax trees for `Resize`, `vision_learner`, and `fine_tune`. [Indexing fix](https://github.com/fastai/fastai/pull/4159) · [Transform fix](https://github.com/fastai/fastai/pull/4167) · [fastai 2.8.12 release](https://pypi.org/project/fastai/2.8.12/)

## Remaining notebooks

The expanded lock was resolved in a temporary project and compared with the validated lesson 00 lock before installation. All prior package versions were retained, including Python 3.12.11, fastai 2.8.12, torch 2.8.0+cpu and torchvision 0.23.0+cpu. Additions cover widgets, Plotly/OLS, seaborn, Graphviz, Kaggle, timm and the Hugging Face stack. Datasets 5.2.0 accepts the existing fsspec version. The separate Windows Graphviz renderer is pinned by release and checksum in [setup_graphviz.ps1](scripts/setup_graphviz.ps1).
